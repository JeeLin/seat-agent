# v0.5.0: 工具完善

## Context
v0.4.0 完成了知识库集成（内存/Qdrant 向量存储 + Embedding + KnowledgeSearchTool），
Agent 已具备「准确性优先」的 RAG 信息基础。

本阶段补全业务侧工具，使 Agent 能够处理真实的客服接待诉求：
**订单查询、退款查询、投诉查询**三类业务系统查询，以及**转人工**闭环。
这是 OCC 客服工作台的核心能力——大部分客户咨询围绕这三类业务展开，
且无法由知识库回答或需人工介入时，必须有明确的转人工出口（AGENTS.md 硬约束：不幻觉、检索不到转人工）。

`Tool` trait 与 `ToolRegistry` 已在 v0.1.0 就绪，`transfer_to_human` 的配置已存在于
`example_tool_config()` 但尚未实现。本里程碑补齐实现并接入 server 启动流程。

版本类型：minor（新增业务工具与转人工工具，向后兼容）

## 产品边界
- 实现业务查询工具：订单查询、退款查询、投诉查询（查询业务系统并格式化结果）
- 实现转人工工具：格式化专业话术并标记转人工出口
- 将三类业务工具 + 转人工工具接入 server 启动流程，与 KnowledgeSearchTool 共存
- 提供可测试的业务后端抽象（trait）+ Mock 实现（用于测试与示例）

**不做什么**：
- 不实现真实业务系统后端服务（OCC 职责，seat-agent 仅通过 HTTP/接口消费）
- 不实现完整的 Agent Loop 调度（v0.2.0 已集成 LLM，但 Loop 编排非本里程碑范围）
- 不实现意图分类（按设计决策，工具直接注册，由 LLM 自行选择调用）
- 不做敏感操作的真实执行（退款/投诉仅查询，不触发写操作）

## 子任务详细设计

### 1 业务后端抽象 + 订单查询工具

- **功能目标**：定义业务系统查询的零依赖抽象 `BusinessBackend`，并提供 Mock 实现用于测试/示例；
  实现 `OrderQueryTool`，根据订单号查询并格式化订单信息。
- **文件结构**：
  - 创建 `crates/core/src/traits.rs` 中新增 `BusinessBackend` trait（`Send + Sync`）
  - 创建 `crates/tools/src/business.rs`（Mock 实现 + 三个业务工具共用后端类型）
  - 修改 `crates/tools/src/lib.rs`，新增 `pub mod business;`
  - 修改 `crates/tools/src/registry.rs`，在 `example_tool_config()` 追加订单查询配置
- **接口设计**：
  ```rust
  // core/src/traits.rs 新增
  #[async_trait]
  pub trait BusinessBackend: Send + Sync {
      async fn query_order(&self, order_id: &str) -> Result<serde_json::Value>;
      async fn query_refund(&self, refund_id: &str) -> Result<serde_json::Value>;
      async fn query_complaint(&self, complaint_id: &str) -> Result<serde_json::Value>;
  }

  // tools/src/business.rs
  pub struct OrderQueryTool { backend: Arc<dyn BusinessBackend> }

  impl OrderQueryTool {
      pub fn new(backend: Arc<dyn BusinessBackend>) -> Self;
  }

  #[async_trait]
  impl Tool for OrderQueryTool {
      fn definition(&self) -> ToolDefinition;
      async fn execute(&self, args: Value) -> Result<String>;
  }

  // Mock 实现（测试 + basic_chat 演示用，返回确定性样本数据）
  pub struct MockBusinessBackend;
  #[async_trait]
  impl BusinessBackend for MockBusinessBackend { /* 内置样例订单/退款/投诉 */ }
  ```
- **实现要点**：
  - `BusinessBackend` 返回 `serde_json::Value`（避免 core 膨胀业务结构；格式化由工具层完成）
  - `OrderQueryTool::definition()` 复用 `example_tool_config()` 中的 `order_query` 结构
    （name/description/parameters/intermediate_reply/error_reply 保持一致）
  - `execute`：`args["order_id"]` → `backend.query_order(...)` →
    将 `Value` 序列化为带字段标签的纯文本（`订单号 / 状态 / 金额 / 下单时间` 等）
  - 订单不存在（`query_order` 返回空/错误）→ 返回 `error_reply` 文案，不编造
  - `MockBusinessBackend` 内置 1-2 条样例订单，使 basic_chat 可演示
- **测试标准**：`OrderQueryTool` 对 `MockBusinessBackend` 的查询返回预期文本；缺失 `order_id` 返回错误；查询不存在订单返回明确提示。
- **提交信息**：`feat(tools): add BusinessBackend trait and OrderQueryTool`

### 4 转人工工具

- **功能目标**：实现 `transfer_to_human` 工具（配置已存在，实现缺失）。
  将 LLM 决策转人工的 `reason` 与回复客户的话术 `reply` 格式化为结构化输出，
  作为 Agent 转人工的出口（AGENTS.md 硬约束：检索不到 / 无法回答时转人工）。
- **文件结构**：创建 `crates/tools/src/transfer.rs`；
  修改 `crates/tools/src/lib.rs`，新增 `pub mod transfer;`
- **接口设计**：
  ```rust
  pub struct TransferToHumanTool;
  impl TransferToHumanTool {
      pub fn new() -> Self;
  }
  #[async_trait]
  impl Tool for TransferToHumanTool {
      fn definition(&self) -> ToolDefinition;
      async fn execute(&self, args: Value) -> Result<String>;
  }
  ```
- **实现要点**：
  - `definition()` 复用 `example_tool_config()` 已有的 `transfer_to_human` 配置
    （name/description/parameters/intermediate_reply/error_reply 保持一致）
  - `execute`：`args["reason"]`（内部记录）+ `args["reply"]`（回复客户话术）；
    返回包含转人工标记与话术的结果文本（如 `<<TRANSFER>>\n{reply}` 或结构化 JSON），
    便于上层识别转人工出口
  - `reason` / `reply` 缺失 → 返回错误（转人工必须有明确原因与话术，避免无意义转接）
  - 话术严格专业化（AGENTS.md 设计决策），工具仅负责格式化与出口标记，不决定何时调用
- **测试标准**：正常参数返回含转人工标记与话术的结果；缺失 `reason` 或 `reply` 返回错误。
- **提交信息**：`feat(tools): implement TransferToHumanTool`

### 5 接入 Agent 工具链路 + 验证

- **功能目标**：在 server 启动时注册全部工具（knowledge_search + order/refund/complaint + transfer），
  使 Agent 工具链路完整；验证全链路编译/测试通过。
- **文件结构**：修改 `crates/server/src/main.rs`
- **接口设计**：
  ```rust
  // main.rs 启动时为每个工具创建实例并注册
  let backend: Arc<dyn BusinessBackend> = Arc::new(MockBusinessBackend::new());
  registry.register(Box::new(OrderQueryTool::new(backend.clone())));
  registry.register(Box::new(RefundQueryTool::new(backend.clone())));
  registry.register(Box::new(ComplaintQueryTool::new(backend.clone())));
  registry.register(Box::new(TransferToHumanTool::new()));
  // knowledge_search 沿用既有注册
  ```
- **实现要点**：
  - 按 `main.rs` 现有模式（Arc + register）逐个注册，保持与 `knowledge_tool` 一致的风格
  - 使用 `MockBusinessBackend` 作为默认业务后端（真实 HTTP 后端为后续里程碑）
  - 确保 `cargo check --workspace`、`cargo clippy --workspace --all-targets -- -D warnings`、
    `cargo test --workspace` 全部通过
- **测试标准**：编译无 error、clippy 无 warning、全量测试通过；注册日志列出全部工具名称。
- **提交信息**：`feat(server): wire business and transfer tools into agent startup`
