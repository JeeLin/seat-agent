# v0.6.0: 测试与示例

## Context
v0.5.0 完成了业务工具（订单/退款/投诉查询 + 转人工），Agent 工具链路已完整：
知识库检索 + 业务查询 + 转人工。

本阶段补齐测试覆盖与示例代码，使项目具备可验证性和可演示性。
当前状态：core crate 仅 vector_store.rs 有 2 个测试，tools crate 有 15 个测试
（business/embedding/knowledge/transfer），server/memory 零测试。
示例仅有 basic_chat（使用 GreetTool 演示 Agent 事件流），无业务工具集成、无语音示例。

版本类型：minor（新增测试与示例，不改变公共 API）

## 产品边界
- 为 core crate 核心模块补充单元测试（agent/context/config/error/mock）
- 为 tools crate registry.rs 补充单元测试
- 创建集成测试，验证跨 crate 的完整 Agent 流程
- 增强 basic_chat 示例，集成全部业务工具，演示完整客服接待场景
- 创建 voice_chat 示例，演示语音模式下的受限 Agent Loop

**不做什么**：
- 不新增公共 API 或功能特性
- 不实现 server crate 的测试（依赖外部基础设施 Redis/gRPC，后续里程碑覆盖）
- 不实现 memory crate 的功能（空壳 crate，保持原样）
- 不修改已有 API 的行为
- 不做性能测试或基准测试

## 子任务详细设计

### 1 Core crate 单元测试

- **功能目标**：为 core crate 中缺少测试的核心模块补充单元测试，
  覆盖 Agent 消息处理流程、Context 分层构建与截断、配置默认值与工厂方法、
  错误类型转换、MockLlmClient 行为。
- **文件结构**：
  - 修改 `crates/core/src/agent.rs`（新增 `#[cfg(test)] mod tests`）
  - 修改 `crates/core/src/context.rs`（新增 `#[cfg(test)] mod tests`）
  - 修改 `crates/core/src/config.rs`（新增 `#[cfg(test)] mod tests`）
  - 修改 `crates/core/src/error.rs`（新增 `#[cfg(test)] mod tests`）
  - 修改 `crates/core/src/mock.rs`（新增 `#[cfg(test)] mod tests`）
- **测试用例设计**：

  **agent.rs**：
  - `test_agent_new_creates_instance`：验证 Agent::new 正确初始化
  - `test_register_tool`：注册工具后可以遍历
  - `test_on_message_direct_reply`：MockLlmClient 返回纯文本（无 tool_call），Agent 直接输出最终回复
  - `test_on_message_tool_call_then_reply`：MockLlmClient 第一次返回 tool_call，第二次返回最终回复
    验证 AgentEvent 序列：StreamStart → ToolCallStart → ToolCallEnd → Token → StreamEnd
  - `test_on_message_transfer_to_human`：LLM 返回 transfer_to_human 调用，验证 TransferToHuman 事件
  - `test_on_message_error_propagation`：MockLlmClient 模拟错误，验证 Error 事件

  **context.rs**：
  - `test_context_new_initializes_with_system_prompt`：验证 Context::new 包含系统提示词
  - `test_context_text_vs_voice_default_prompt`：Text 和 Voice 模式使用不同的默认提示词
  - `test_add_user_message`：用户消息正确入队到 history
  - `test_add_assistant_message`：助手消息正确入队到 history
  - `test_add_tool_result`：工具结果正确入队到 working
  - `test_build_messages_order`：build_messages 的消息顺序正确（system → summary → retrieval → history → working）
  - `test_build_messages_with_retrieval`：检索结果作为系统消息注入
  - `test_build_messages_with_history_summary`：历史摘要作为系统消息注入
  - `test_flush_working_to_history`：工作区内容正确迁移到 history
  - `test_clear_working`：工作区正确清空
  - `test_truncate_history`：截断历史消息，保留 min_history_messages
  - `test_estimate_tokens`：token 估算基于字符数/4

  **config.rs**：
  - `test_default_config`：默认配置字段正确（Text, max_rounds=10, max_duration=30s 等）
  - `test_config_text_factory`：text() 返回默认配置
  - `test_config_voice_factory`：voice() 返回 Voice 模式，max_rounds=2，max_output_tokens=200
  - `test_config_serialization`：AgentConfig 可序列化和反序列化

  **error.rs**：
  - `test_error_display`：各错误变体的 Display 格式正确
  - `test_error_from_serde_json`：serde_json::Error 自动转换为 AgentError::Serialization

  **mock.rs**：
  - `test_mock_llm_returns_preset_responses`：按顺序返回预设响应
  - `test_mock_llm_cycles_responses`：超过预设数量时循环返回
  - `test_mock_llm_error_mode`：with_error 模式返回错误
  - `test_mock_llm_with_delay`：with_delay 添加延迟（验证流式输出不阻塞）

- **测试标准**：全部测试通过；每个测试有明确的断言，覆盖正常路径和边界情况。
- **提交信息**：`test(core): add unit tests for agent, context, config, error, mock`

### 4 basic_chat 示例增强

- **功能目标**：升级 basic_chat 示例，使用完整的业务工具集（知识库检索、订单查询、
  退款查询、投诉查询、转人工），演示真实客服接待场景，
  替换当前的 GreetTool 演示。
- **文件结构**：
  - 修改 `examples/basic_chat/src/main.rs`
  - 修改 `examples/basic_chat/Cargo.toml`（新增依赖：seat-agent-tools）
- **接口设计**：
  ```rust
  // 使用 MockLlmClient 预设客服场景的多轮对话：
  // 1. 客户："我想查一下订单 20240308001"
  //    → LLM 返回 order_query tool_call
  //    → 订单查询结果
  // 2. LLM 根据结果回复客户
  // 3. 客户："这个订单能退款吗？"
  //    → LLM 返回 refund_query tool_call
  //    → 退款查询结果
  // 4. LLM 根据结果回复客户
  ```
- **实现要点**：
  - 导入 `seat_agent_tools` 的 business、knowledge、transfer 模块
  - 使用 `MockBusinessBackend` 创建业务工具
  - 使用 `MockLlmClient` 预设多轮客服对话的 LLM 响应
  - 注册全部工具（knowledge_search + order/refund/complaint_query + transfer_to_human）
  - 保持现有 AgentEvent 处理逻辑，展示完整的客服对话流程
  - 输出格式清晰，标注每个工具调用的结果
- **测试标准**：`cargo run --example basic_chat` 正常运行，输出完整的多轮客服对话。
- **提交信息**：`examples: enhance basic_chat with business tools`

### 5 voice_chat 示例

- **功能目标**：创建语音对话示例，演示 Voice 模式下的受限 Agent Loop
  （最多 2 轮工具调用），展示语音模态的配置和事件处理差异。
- **文件结构**：
  - 创建 `examples/voice_chat/Cargo.toml`
  - 创建 `examples/voice_chat/src/main.rs`
- **接口设计**：
  ```rust
  // 使用 AgentConfig::voice() 配置
  // MockLlmClient 预设语音场景：
  // 1. 模拟 ASR 输入文本
  // 2. LLM 调用订单查询
  // 3. LLM 返回最终回复
  // 展示 Voice 模式下 max_rounds=2 的限制
  ```
- **实现要点**：
  - 使用 `AgentConfig::voice()` 配置（max_rounds=2, max_output_tokens=200）
  - MockLlmClient 模拟语音客服场景
  - 注册业务工具和转人工工具（语音场景不注册知识库工具以简化演示）
  - AgentEvent 处理与 basic_chat 一致，但注释说明语音模态的差异
  - 在 main 函数中通过注释说明语音模式的特殊行为（max_rounds 限制、中间回复的 audio_cue）
  - 添加 voice 模式特有的系统提示词说明
- **测试标准**：`cargo run --example voice_chat` 正常运行，演示受限 Agent Loop。
- **提交信息**：`examples: add voice_chat example for voice modality`
